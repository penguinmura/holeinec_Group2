# hole-in-EC

ウェブアプリケーションの脆弱性を体験し、セキュアコーディングや堅牢な設計（Security by Design）を学ぶための「実践型やられECサイト」のデモプロジェクトです。
バックエンド（Express + Prisma + SQLite）とフロントエンド（React + Vite）で構成されています。

## 技術スタック
- **Frontend:** React (v18.x), Vite, Axios, React Router
- **Backend:** Node.js (v20.x), Express (v4.x), Prisma (v5.x), SQLite
- **Security:** bcrypt (パスワードハッシュ化), JSON Web Token (JWT認証), zod (入力値バリデーション)

## 単体テストの実行について
このプロジェクトでは、バックエンド（Node.js/Express）のロジックを検証するための単体テスト環境として **Jest** を導入しています。

### テストの仕組み
- 単体テストでは実際のデータベース（SQLite）には接続しません。代わりに `jest.mock()` を用いて **Prismaクライアントをモック化（偽装）** しています。これにより、ローカルのDBの状態に依存せず、安定して高速にテストを実行できます。
- テストファイルは対象となるロジックファイルの隣に配置しています（例: `server/src/services/user.service.test.js`）。

### テストの実行方法
サーバーディレクトリに移動し、以下のコマンドを実行するだけで全ての単体テストが実行されます。

```bash
cd /Users/fukuchiosamutaira/work/hole-in-ec/server
npm test
```

## ロギング機能について
バックエンドでは、エンタープライズ標準のロガー（Winston + Morgan）を用いた**構造化ロギング**を実装しています。
- **ログファイルの役割分離**:
  - `server/logs/app.log`: 認証、決済、管理者操作などの重要なビジネスイベント（監査ログ）を記録します。
  - `server/logs/access.log`: 全てのAPIアクセス履歴（HTTPリクエスト情報）を記録します。
  - `server/logs/error.log`: スタックトレースを含む深刻なシステムエラーを記録します。
- **構造化ロギング（JSON）**: `app.log` などのビジネスイベントは、単なる文字列ではなくメタデータ（`category` や `action` 等）を含んだJSON形式でログを出力することで、監視ツール等での検索・集計を容易にしています。

## セキュアコーディング演習について
このブランチ（`vuln-practice`）では、学習のために意図的に複数のセキュリティ上の欠陥や設定不備（バリデーションの不備、競合状態、SQLインジェクション、XSS、IDOR等）が埋め込まれています。

### 演習の流れ：
1. **発見（検知）**: Kibanaなどのダッシュボードで異常なアクセスログを観察したり、手動でアプリを操作して脆弱性を特定します。
2. **原因分析**: ソースコードを読み、どこにバグや設計の穴があるか特定します。
3. **修正と検証**: コードをセキュアな形に修正し、テストスイート（`npm test`）を実行して正しく機能することを確認します。
4. **デプロイ**: 修正版をプッシュして、デプロイ後の実環境で脆弱性が塞がれたことを確認します。
