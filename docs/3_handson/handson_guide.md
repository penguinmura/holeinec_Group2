## 💻 サーバーサイド (Node.js/Express) のソースコード構成

インシデントの原因となっているプログラムは、すべて `server/src/` ディレクトリ配下にあります。
本システムは、以下のような典型的な **「ルーティング層」「コントローラー層」「サービス層」** の3層構造で設計されています。

```text
server/src/
  ├── app.js                    # Expressアプリケーション全体の初期設定、ミドルウェア（CSP等）の読み込み
  ├── routes/                   # 各APIエンドポイントの定義（どのパスでどの処理を呼ぶか）
  ├── controllers/              # HTTPリクエストの受信、バリデーション、レスポンス送信
  └── services/                 # データベースアクセス、ビジネスロジックの実行
```

## 🔍 各コントローラー・サービスの役割一覧

「この機能が怪しい」「この挙動を調べたい」となった際、ソースコードのどこを重点的に読めばよいかの早見表です。

### 1. Controllers (`server/src/controllers/`)
クライアント（画面）からのリクエストを受け取り、バリデーションチェックやエラーハンドリングを行ってレスポンスを返します。

*   **`auth.controller.js`**: ユーザー登録、ログイン、およびパスワードリセット等の認証・セッション関連処理。
*   **`cart.controller.js`**: カートへの商品追加、数量変更、削除などのカート操作リクエスト。
*   **`order.controller.js`**: カート情報をもとにした注文・決済処理のリクエスト受付。
*   **`user.controller.js`**: マイページにおけるプロフィール情報の取得・変更処理の制御。
*   **`product.controller.js`**: 商品の閲覧、レビュー投稿の制御。
*   **`admin.controller.js`**: 管理者専用機能（商品の追加・編集・削除など）のリクエスト受付。
*   **`inquiry.controller.js`**: お問い合わせ送信、および管理者によるお問い合わせ一覧の取得処理。

### 2. Services (`server/src/services/`)
コントローラーから呼び出され、データベース（Prismaクライアント経由）との直接のやり取りを含めた、**本質的なロジックや計算**を処理します。

*   **`auth.service.js`**: パスワードのハッシュ化・照合や、パスワードリセット時の本人確認のためのDB検証ロジック。
*   **`cart.service.js`**: カート内データの取得、追加、更新、削除等のデータベース処理ロジック。
*   **`order.service.js`**: 在庫数のチェック、注文レコードの作成、在庫減算、および決済シミュレーション処理。
*   **`user.service.js`**: プロフィール情報のデータベース更新ロジック。
*   **`product.service.js`**: 商品やレビュー情報のDB取得・追加ロジック。
*   **`admin.service.js`**: 管理者権限による商品の登録・編集・削除などのデータベース処理ロジック。
*   **`inquiry.service.js`**: お問い合わせ内容のDB保存、および管理者向けお問い合わせ情報のデータベース抽出ロジック。

## 💡 調査・修正時の注意点 (境界線)
*   **サーバーサイドの修正だけで解決可能**:
    今回のワークショップで発生しているすべての脆弱性・不具合は、`server/src/` 配下の JavaScript コードを修正するだけで解決できます。フロントエンド（`client/`）やデータベースのテーブル構造（`prisma/schema.prisma`）を修正する必要はありません。
