# 🛍️ やられアプリ構成・実装解説ガイド (参加者向け)

本ガイドは、やられECサイト「hole-in-EC」のシステム全体の構成と、特にサーバー（バックエンド）サイドのプログラム構造について解説した資料です。

参加者の皆様が、コードのどのレイヤーを調査すれば良いか（探索範囲）の全体像を把握し、円滑にセキュアコーディングに取り組めるように作成されています。

---

## 1. やられECサイト「hole-in-EC」の主な機能

本アプリケーションは、一般的なECサイトで必要とされる以下の基本機能を備えています。

*   **ユーザー認証機能**: 新規会員登録、ログイン、ログアウト、パスワードリセット。
*   **商品閲覧・レビュー機能**: 商品一覧・詳細の表示、および購入された商品に対するカスタマーレビュー（評価とコメント）の投稿。
*   **カート・注文決済機能**: 商品をカートに追加し、数量を指定して注文・決済（決済処理のシミュレーション）を行う機能。
*   **プロフィール編集機能**: マイページから、登録されているユーザー情報（ユーザー名やメールアドレスなど）を更新する機能。
*   **お問い合わせ機能**: サイト上のフォームから、運営（サポートチーム）に向けて問い合わせメッセージを送信する機能。
*   **管理者向け機能**: 管理者アカウントでログインすることで、専用の管理画面（ダッシュボード）にアクセスし、商品の追加・編集・削除（在庫更新など）や、ユーザーから寄せられたお問い合わせを閲覧する機能。

---

## 2. アプリケーション全体の技術構成

本アプリケーションは、以下のような典型的なモダンWebアプリケーションの構成を採用しています。

*   **フロントエンド (クライアントサイド)**: React + Vite (Vanilla CSS)
*   **バックエンド (サーバーサイド)**: Node.js + Express
*   **データベース / ORM**: SQLite + Prisma

---

## 3. サーバーサイド (Node.js/Express) の実装構成

修正の中心となるバックエンドサーバー（`server/` ディレクトリ配下）は、以下のようなレイヤー化アーキテクチャで構成されています。

```text
client/ (Reactフロントエンド)
  │
  ▼ [HTTP Request] (ポート 3000 宛て)
server/src/
  ├── app.js                    # Expressアプリケーションの初期化・ミドルウェア設定
  ├── routes/                   # ① ルーティング層 (APIエンドポイントの定義)
  ├── controllers/              # ② コントローラー層 (リクエストのバリデーション、レスポンス返却)
  └── services/                 # ③ サービス層 (実際のビジネスロジック、DBアクセス)
        │
        ▼ [Prisma クエリ実行]
      prisma/schema.prisma      # データベース定義 (SQLite / Prisma schema)
```

### 📂 各ディレクトリの役割と編集方針

1.  **`routes/` (ルーティング層)**
    *   `auth.routes.js`, `order.routes.js` など。
    *   特定のパス（例: `POST /api/orders`）に対して、どのコントローラーを実行し、どの認証・認可ミドルウェア（`auth.middleware.js` など）を挟むかを定義しています。
2.  **`controllers/` (コントローラー層)**
    *   `auth.controller.js`, `order.controller.js` など。
    *   HTTPリクエストの受付、ヘッダー/ボディの解析、およびフロントエンドへのレスポンス送信を担当します。
    *   *💡 修正のヒント: リクエストデータの受け取りや、その入力バリデーション、およびクライアントへのステータスコードやレスポンスの返却ロジックを制御したい場合は、主にここを修正します。*
    *   **各コントローラーの主な役割**:
        *   `auth.controller.js`: 会員登録、ログイン、およびパスワードリセットなどの認証・セッション関連処理。
        *   `cart.controller.js`: カートへの商品追加、数量変更、削除などのカート操作リクエスト。
        *   `order.controller.js`: カート情報をもとにした注文・決済処理のリクエスト受付。
        *   `user.controller.js`: マイページにおけるプロフィール情報の取得・変更処理の制御。
        *   `product.controller.js`: 商品の閲覧、レビュー投稿の制御。
        *   `admin.controller.js`: 管理者専用機能（商品の追加・編集・削除など）のリクエスト受付。
        *   `inquiry.controller.js`: お問い合わせ送信、および管理者によるお問い合わせ一覧の取得処理。

3.  **`services/` (サービス層) ★最重要**
    *   `auth.service.js`, `order.service.js` など。
    *   データベース（Prismaクライアント）との直接のやり取りを含め、ログイン認証の判定や注文手続きの裏側など、**本質的なビジネスロジック**がここに集約されています。
    *   *💡 修正のヒント: データベースに対するクエリ操作、各種機能のコアとなるビジネスロジックやデータ処理のロジック、エラー発生時の詳細な内部処理などを変更したい場合は、主にここを修正します。*
    *   **各サービスの主な役割**:
        *   `auth.service.js`: パスワードの照合や、パスワードリセット時の本人確認のためのDB検証ロジック。
        *   `cart.service.js`: カート内データの取得、追加、更新、削除等のデータベース処理ロジック。
        *   `order.service.js`: 在庫数のチェック、注文レコードの作成、在庫減算、およびシミュレーション決済の裏側ロジック。
        *   `user.service.js`: プロフィール情報のデータベース更新ロジック。
        *   `product.service.js`: 商品やレビュー情報のDB取得・追加ロジック。
        *   `admin.service.js`: 管理者権限による商品の登録・編集・削除などのデータベース処理ロジック。
        *   `inquiry.service.js`: お問い合わせ内容のDB保存、および管理者向けお問い合わせ情報のデータベース抽出ロジック。

## 🛡️ ワークショップにおける「調査・修正の境界線」

無駄な調査で時間を浪費しないよう、以下の境界線（スコープ）をあらかじめ頭に入れておいてください。

### 🟢 サーバーサイド（バックエンド）の修正だけで解決します
今回のワークショップで発生しているすべての脆弱性・不具合は、**サーバーサイド（`server/src/` 配下）のコードを適切に修正するだけで 100% 解決・防御することが可能**です。

### ❌ 修正不要なレイヤー (触らなくて良い部分)
*   **データベーススキーマ (`server/prisma/schema.prisma`)**:
    テーブル構造の追加・削除や、Prismaマイグレーションを実行し直す必要があるような脆弱性は含まれていません。
*   **フロントエンド（React / `client/` 配下）**:
    画面のUIやボタンの配置、Reactコンポーネントのコードを修正する必要はありません。（※一部、画面の挙動がバグっているように見えても、すべてサーバー側のAPIが不正なレスポンスを返していることが原因です。サーバー側を直せば画面も自動的に正常化します。）
