# 📊 Kibana (Elasticsearch) 登録済みログビュー閲覧ガイド

本ガイドは、やられECサイト「hole-in-EC」のインシデント調査で使用する **Kibana（Elasticsearch）にあらかじめ登録されている3つのログビューおよびダッシュボード** の確認方法と、それぞれのログの解説です。

本ワークショップでは、参加者が手動で検索クエリやカラムを設定する必要はありません。用意された登録済みビューを切り替えながら調査を進めてください。

---

## 1. 登録済みログビューの確認方法

Kibanaにアクセスしたら、以下の手順で登録済みのログビューを切り替えて閲覧します。

### 🔎 Discover で特定のビューを開く手順
1. 左メニューから **[Analytics] ➔ [Discover]** を開きます。
2. 画面上部にあるメニューから **[Open]**（またはフォルダのアイコン）をクリックします。
3. 以下のリストから、現在調査したいログビューを選択します。
   * **`[Group1] アクセスログ`**
   * **`[Group1] 通常アプリログ`**
   * **`[Group1] エラーログ`**
4. 選択すると、検索クエリとカラム（列）があらかじめ整形された状態でログが表示されます。



## 2. 3つの登録済みログビューの解説

各ビューがどのようなログを出力しており、インシデント調査において何に注目すべきかを解説します。

### ① アクセスログ (Access Logs)
* **どのようなログか**:
  Webサーバー（Nginx等）やExpressのミドルウェア（Morgan）が出力した、サーバーが受信したすべてのHTTPリクエストの履歴です。
* **主な表示項目**:
  * `@timestamp` (リクエスト発生日時)
  * `message` (送信元IP、HTTPメソッド、リクエストURL、ステータスコード、応答時間など)
  * *※ なお、HTTPリクエストボディ（POSTやPUTで送信された本文データ）は、アクセスログには記録されません。*

### ② 通常アプリログ (Application Logs)
* **どのようなログか**:
  アプリケーション（Node.js / Express）内部のプログラム（サービスやコントローラー）が、ユーザーのログインや注文、レビューなどの業務イベントが発生した際に独自に出力した動作記録です。
* **主な表示項目**:
  * `@timestamp` (ログ発生日時)
  * `level` (ログの重要度: info, warn 等)
  * `category` (ログの分類: auth, order, product, admin 等)
  * `message` (処理の具体的な説明。注文内容、お問い合わせ本文など)

### ③ エラーログ (Error Logs)
* **どのようなログか**:
  アプリケーション内で予期せぬ例外（Exception）が発生したり、データベースのクエリ実行が失敗したりした際に出力されるシステムエラーログです。
* **主な表示項目**:
  * `@timestamp` (エラー発生日時)
  * `message` (エラーメッセージの詳細)
  * `stack` (例外が発生したプログラムの位置を示すスタックトレース)

## 💡 ログ調査時のTips

### 🕒 時間範囲（Time Range）を適切に合わせる
Kibanaの画面右上にある「カレンダー・時間選択ツール」（デフォルトでは「Last 15 minutes」等）をクリックし、**インシデントが発生したと思われる時間帯（例: 今日全体、または特定の1時間）** に時間範囲を広げてください。ここが狭すぎると、過去の攻撃ログが表示されず見失う原因になります。

### 🔍 ログの詳細（JSON）を展開する
一覧に表示されているログの左端にある **`>` (Expand)** ボタンをクリックすると、そのログのすべてのメタデータ（フィールド）がテーブルまたは JSON 形式で展開されます。message列に表示しきれなかった詳細な注文データや、ユーザーのUUID、詳細なエラー構造などは、ここを展開することで確認できます。
