# GitHub Codespaces 利用ガイド (参加者向け)

本ワークショップでは、PCの環境構築を一切行わず、ブラウザだけで開発ができる **GitHub Codespaces** を使用します。
本ガイドでは、Codespaces の起動から、アプリの動かし方、共同編集の方法、トラブル時の対応策までをまとめています。

---

## 1. Codespace の起動方法

1. ブラウザで配布された GitHub のリポジトリ画面を開きます。
2. 画面左上のブランチ選択メニューから、各自の作業ブランチ（例: `vuln-practice`）を選択します。
3. 画面右上にある緑色の **`[ <> Code ]`** ボタンをクリックします。
4. **`[ Codespaces ]`** タブを選択し、**`[ Create codespace on <ブランチ名> ]`** をクリックします。
5. 数十秒でブラウザ上に VS Code の画面が立ち上がります。

> [!NOTE]
> 初回起動時、裏で自動的にパッケージのインストール（`npm install`）が実行されます。完了するまで約 1〜2 分ほどお待ちください。

---

## 2. データベースの初期化と環境設定

Codespace を初めて起動した際、データベースやログイン用の秘密鍵（環境変数）の設定がないため、以下の初期設定を行います。

VS Code のターミナル（画面下部）で、以下を実行します。

```bash
# 1. serverディレクトリに移動
cd server

# 2. データベースを初期化します
npx prisma migrate dev --name init
```

* 実行が完了すると、テスト用の商品データや管理者アカウント（`admin@example.com` / パスワード `admin1234`）が自動でデータベースに登録されます。

---

## 3. アプリケーションの起動とプレビュー確認

バックエンドとフロントエンドを起動し、ブラウザで動作確認を行います。

### ① バックエンド (API) の起動
新しいターミナルを開き、以下を実行します。
```bash
cd server
npm run dev
```

### ② フロントエンド (React) の起動
ターミナルの「＋」ボタンを押して**もう一つ新しいターミナル**を開き、以下を実行します。
```bash
cd client
npm run dev
```

### ③ ポートの公開範囲 (Visibility) を「パブリック」に変更する (重要)

Codespaces の初期設定ではポートへの通信が制限されているため、そのままではフロントエンドとバックエンド (API) 間の通信がブロックされ、CORSエラーやログイン・商品表示の失敗が発生します。
アプリケーションを動かす前に、以下の手順でポートをパブリックに変更してください。

1. VS Code 画面の下部パネルにある **`[ ポート (Ports) ]`** タブを開きます。
2. ポート **`3000`** (Express Backend) と **`5173`** (React Frontend) の行の **「公開範囲 (Visibility)」** 列を右クリックします。
3. **`[ ポートの公開範囲 (Port Visibility) ]`** ➔ **`「パブリック (Public)」`** を選択します。

### ④ ブラウザで動作確認する

フロントエンドが起動すると、画面の右下に **「Open in Browser (ブラウザで開く)」** というポップアップが表示されるのでクリックします。別タブでECサイトのプレビュー画面が開きます。

* **ポップアップが表示されない・消えてしまった場合:**
  VS Code 画面下部の **`[ポート (Ports)]`** タブを開き、`5173` ポートの横にある **`地球儀のアイコン`** をクリックすることで、いつでもプレビューを開けます。

## 4. グループメンバーでの共同編集 (Live Share)

Codespaces 上で、Google ドキュメントのように複数人でリアルタイムに同じコードを共同編集できます。

1. VS Code 画面左端にある **`Live Share`** アイコンをクリックします。
2. **`[ コラボレーションセッションの開始 (Start Collaboration Session) ]`** をクリックします。
3. 画面右下に招待リンクがコピーされるので、同じグループのメンバーに共有します。
4. リンクを受け取ったメンバーは、ブラウザでそのリンクを開くだけで、同じエディタに入って共同編集を開始できます。

## 5. トラブルシューティング

### Q1. 文字を打つたびに画面がリロードされたり、新規タブが開いてしまう
* **原因:** ブラウザのキーボード拡張機能（**Vimium** など）が、VS Code のエディタ入力を検知できず暴走しています。
* **解決策:** 
  1. ブラウザ右上の **Vimium（青いVのマーク）** の拡張機能アイコンをクリックします。
  2. **`[ Disable Vimium on this domain ]`** (このドメインで無効化) をクリックします。
  3. **`[ Save Changes ]`** をクリックし、ページをリロードします。

### Q2. 動作が重い、文字を入力するたびに「Setting up your codespace...」と出て接続が切れる
クラウド上のマシンスペック（2コア・メモリ4GB）の限界で、コードの自動解析（tsserver）や拡張機能の処理でパンクしています。

* **対策 A: マシンスペックを 4コア に上げる (推奨)**
  1. 画面左下の **`「歯車マーク」`** ➔ **`「マシンタイプの変更 (Change Machine Type)」`** を選択します。
  2. マシンスペックを `2-core` から **`「4-core」`** に変更します。自動的にサーバーがアップグレードされ、再接続します（数秒で完了します）。
* **対策 B: デスクトップ版の VS Code で開く**
  ブラウザの動作制限から解放され、ローカルと全く同じサクサク感で開発できます。
  1. 画面左上の **`「三本線メニュー」`** をクリックします。
  2. **`「VS Code で開く (Open in VS Code)」`** を選択すると、お使いのPCのVS CodeアプリからCodespaceに接続して安全に作業できます。

### Q3. コードを書き換えたのに、画面に反映されない
* **原因:** VS Code の自動保存がオフになっているため、ファイルが保存されていません。
* **解決策:** 編集完了後、必ず **`Cmd + S`** (Mac) または **`Ctrl + S`** (Windows) を押して保存を実行してください。

### Q4. 「商品の取得に失敗しました」と表示され、開発者ツールでCORSエラーやリダイレクトエラー(302)が出ている
* **原因:** Codespace上の転送ポートが「プライベート (Private)」設定になっているため、APIリクエストがGitHubのログイン制限によって遮断されています。また、サーバー側でCodespaceのドメインが許可されていない場合も同様にCORSエラーが発生します。
* **解決策:** 
  1. VS Code 画面の下部パネルにある **`[ ポート (Ports) ]`** タブを開きます。
  2. ポート **`3000`** の行の **「公開範囲 (Visibility)」** 列を右クリックします。
  3. **`[ ポートの公開範囲 (Port Visibility) ]`** ➔ **`「パブリック (Public)」`** を選択します。
  4. 同様に、ポート **`5173`** も「パブリック (Public)」に変更します。
  5. **最新のコードを取得しているか確認してください**: サーバー側のCORS設定でCodespaceのドメイン（`*.github.dev`）が許可されている必要があります。最新の `vuln-practice` ブランチの内容を `git pull` 等で同期してください。
  6. アプリのブラウザ画面をリロードすると、CORSエラーが消えて正常に表示されます。
  *(※今後新しく作成するCodespacesでは自動的にパブリックに設定されるため、この手動手順は不要になります)*

### Q5. ログイン画面への遷移やアクセス時に「ENOENT: no such file or directory, stat .../client/dist/index.html」というエラーが出る
* **原因:** フロントエンド（React/Vite）のビルド成果物（`client/dist`）が生成されていないため、バックエンドのExpressサーバーが画面用のHTMLを配信できていません。
* **解決策:** 
  1. VS Codeの新しいターミナルを開きます。
  2. 以下のコマンドを実行して、フロントエンドのビルドファイルを生成します。
     ```bash
     cd client
     npm run build
     ```
  3. ビルドが成功すると `client/dist` ディレクトリが作成され、Expressサーバー経由でのページ遷移やリダイレクト（`/login` など）がエラーなく正常に動作するようになります。

## 6. Codespaces の無料枠と使用状況の確認方法

GitHub では、すべての個人アカウントに対して毎月 **60コア時間 (Core-hours)** の計算時間と、**15GB** のストレージが無料で提供されています。
* 2コア (標準) マシンなら: **毎月 30時間** まで無料
* 4コア マシンなら: **毎月 15時間** まで無料

残り時間がどれくらいあるかは、以下の手順でいつでもブラウザから確認できます。

1. [GitHub](https://github.com/) にブラウザでログインします。
2. 画面右上の **「自分のプロフィールアイコン」** ➔ **`[ Settings (設定) ]`** をクリックします。
3. 左メニューの **`[ Billing and plans (支払いとプラン) ]`** ➔ **`[ Plans and usage (プランと使用量) ]`** をクリックします.
4. 画面を少し下へスクロールすると、**`「Codespaces」`** というセクションがあり、当月に使用した計算時間（Core hours）とストレージ容量のパーセンテージ（残り状況）を確認できます。

## 7. ポート公開に伴うセキュリティリスクと安全な運用ルール

フロントエンドとバックエンドの通信（CORS回避）のため、転送ポートの公開範囲を「パブリック (Public)」に設定しています。
本アプリケーションは「意図的に脆弱性を埋め込んだやられアプリ」であるため、**ポートが公開されている間は、URLを知っている第三者から攻撃を受けるリスクが存在します。**

リソースの不正消費（マイニングへの悪用など）や外部への踏み台化を防ぐため、以下の**安全運用ルール**を必ず守ってください。

### 🛡️ 安全運用のための3大ルール

#### ルール①：使い終わったら必ずブラウザを閉じる（自動シャットダウンの活用）
Codespaces は、**ブラウザのタブを閉じてから 30分間操作がないと、自動的にコンテナがシャットダウン（停止）する**仕様になっています。
* 停止している間は CPU も時間も一切消費せず、外部からアクセスされることもありません。
* 手動で即座に停止したい場合は、VS Code 画面左下の **`「歯車マーク」`** ➔ **`[ Stop Current Codespace (現在のCodespaceを停止) ]`** をクリックしてください。

#### ルール②：ワークショップ終了後は Codespace を完全に削除する
Codespace を停止していても、作成したコンテナの「ファイル容量（ストレージ）」は毎月の無料枠（15GB）を消費し続けます。
* ワークショップや演習が完全に終了したら、必ず [GitHub Codespaces 管理画面](https://github.com/codespaces) を開き、不要になったコンテナの横の「...」から **`[ Delete (削除) ]`** を行って環境を完全に消去してください。

#### ルール③：課金上限（Spending Limit）を $0 に設定しておく（推奨）
万が一無料枠を使い切ってしまった場合や、不正利用が起きた場合のクレジットカードへの自動請求を防ぎます。
1. **「自分のプロフィールアイコン」** ➔ **`[ Settings ]`** ➔ **`[ Billing and plans ]`** を開きます。
2. **`[ Spending limit (課金上限) ]`** の設定を見つけ、値を **`0`** (ドル) に設定して保存します。
3. これにより、無料枠の上限に達した時点で自動的に Codespace がロックされ、予期せぬ超過課金を 100% ブロックできます。
